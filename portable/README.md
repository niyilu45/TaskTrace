# TaskTrace 本机体验版

本包基于 Vikunja，适用于 Windows x64。使用时不需要安装 Node.js、Go、Docker 或数据库；使用系统自带 PowerShell 和浏览器。

## 启动与退出
1. 将整个 ZIP 解压到可写目录，不要直接在压缩包中运行。
2. 双击带小羊驼图标的 TaskTrace.exe。
   如果已有 TaskTrace 或旧版本运行（包括隐藏在系统托盘中），会提示“已有程序正在运行”，不会再启动第二份；请先从托盘选择“退出 TaskTrace”，再启动新版。不同解压目录也会检测。
3. 同时打开置顶悬浮窗和浏览器完整界面，无需注册、账号或密码，共用同一份数据。
4. 关闭浏览器不影响悬浮窗；悬浮窗不显示在任务栏；点击关闭或最小化按钮只会隐藏到系统托盘；停止服务请在托盘菜单选择“退出 TaskTrace”。
5. 下次仍使用同一目录启动，账号、事项、附件会保留。

默认地址为 http://127.0.0.1:3456；被占用时自动选择 3457–3476，实际地址显示在启动窗口中。
本机体验仅监听 127.0.0.1，其他电脑不能直接连接本机服务。团队任务通过程序旁的 `teamData` Windows 共享文件夹在局域网内交换，每个人仍使用自己的本地数据库和任务树。

所有可输入文字的文本框上方都保留字段说明；文本框内的浅色提示只用于举例，输入内容后字段含义仍然可见。后续新增文本框也应遵循这一规则。

## 悬浮窗模式
统一双击 TaskTrace.exe，同时打开完整界面和默认置顶的原生 Windows 小窗，无需账号登录。切换其他软件后仍可见，可拖动标题栏、调整窗口大小，位置与大小会自动保存。

- 顶部选择项目；点击底部“新事项”后输入名称、选择优先级，再按回车或点击“添加事项”。上次选择的项目会记住，重启后恢复。
- 勾选事项即标记完成，不会改写已有描述和进展。
- 任务状态支持待办（to-do）、进行中（doing）、暂停（hold）和已完成（done）。完整界面在任务详情中直接选择；悬浮窗右键任务选择“设置任务状态”。状态会显示在任务行中；完成勾选框与 done 状态保持同步，取消完成后回到 to-do。
- 任务、子任务和遗留事项均显示完成勾选框；可用鼠标点击，或选中后按空格切换完成状态。
- 项目旁的“显示已完成”开关默认关闭；开启后同时显示已完成事项，可取消事项勾选恢复为未完成。开关状态会保留到下次启动。
- 任务以树形层级显示，子任务逐级缩进；点击任务旁的展开/收起按钮，或用键盘左右方向键操作。展开状态会自动保存。
- 完整悬浮窗可勾选“单行显示”；任务会按“当前任务 / 父任务 / 更上级任务”显示，当前任务使用黑色，上级路径使用淡灰色。该选择会保存，并同步用于简洁模式。遗留事项在两种模式中均使用粗体。
- 搜索会保留匹配子任务的父任务并临时展开；有未完成子任务的已完成父任务会作为层级提示保留。
- 每页最多 50 个顶层任务组，同一任务下的子任务不会拆到另一页；勾选任务只切换该任务自身的完成状态。
- 完整悬浮窗调整宽度时，项目选择、新事项、查找事项和底部操作栏会同步伸缩；从宽窗口缩回窄窗口后不会保留旧宽度或产生空白。
- 完整和简洁悬浮窗共用同一棵任务树、筛选、展开/收起、遗留事项、图片和拖放逻辑；切换只调整窗口布局及按钮显示，不重新读取任务，保留选中项、展开状态和滚动位置。简洁模式底部保留“完整”和“最小化”；“最小化”会隐藏到系统托盘。完整悬浮窗顶部固定为“完整界面、置顶、设置、简洁模式”一行，不保留空白按钮行；记录进展和新建操作集中在底部。
- “置顶”可开关；关闭或最小化后隐藏到系统托盘，可双击托盘图标或通过托盘菜单“显示悬浮窗”恢复。
- 托盘右键可选择“重置悬浮窗位置”，窗口会回到当前显示器工作区中央；“边缘隐藏”可勾选并保存在本机设置中。启用后，把悬浮窗拖到当前显示器工作区任一边缘，松开鼠标后窗口会收至屏幕外；鼠标移到原窗口对应的边缘区段时恢复，未在窗口中操作且鼠标离开后会再次收起。
- “完整界面”免登录打开浏览器，用于图片、详细进展和其他功能；两种界面使用相同数据库。
- 仅在本机数据发生变化后自动同步，连续修改会合并处理。无变化时不重新加载列表；同步期间保持可操作，并保留选中项、滚动位置和收起状态。按 F5 可立即同步，包括新建的项目。
- 点击窗口关闭按钮只会隐藏到系统托盘，后台服务继续运行；托盘“退出 TaskTrace”才会停止本机服务。

两个界面共用一个后台服务，无需分别启动。浏览器关闭后，可从悬浮窗或托盘的“完整界面”再次打开。

## 检查更新

- 程序启动时会检查 GitHub Releases，之后按“完整界面 → 设置 → 更新设置”中的间隔继续检查，默认每 60 分钟一次。
- 可在更新设置页或系统托盘右键菜单中选择“检查更新”。发现新版本时会显示版本号、发布日期和发布说明。
- 拒绝某个版本后，自动检查不会再次提醒该版本；主动检查仍会显示当前结果。
- 确认更新后会使用 Windows 系统代理下载发布包并校验 `SHA256SUMS.txt`。程序会再次说明需要关闭 TaskTrace；选择不关闭会取消本次更新。
- 更新器只替换程序文件，保留 `data`、`tasktrace-settings.json` 和更新设置，完成后自动重新启动。
悬浮窗使用 Windows 自带 .NET Framework 4.x，不包含 Electron 或 Node.js。建议 Windows 10/11 x64。

## 局域网团队协作

- 程序首次启动会在程序目录创建 `teamData`。在 Windows 文件夹属性的“共享”和“安全”页面中给协作成员读写权限；重启 TaskTrace 后，任务详情会自动列出从文件夹权限发现的候选用户名，并在任务链接中使用检测到的 UNC 共享路径。
- 打开完整界面的任务详情，在“团队协作”中选择或填写至少一位其他成员，再点击“共享当前任务”。程序只共享当前任务及其子任务、描述、进展、评论、遗留事项和其中的图片附件，不会共享父任务、同级任务或其他未选任务。
- 把生成的 `tasktrace-team://` 任务链接发给成员。接收者点击完整界面顶部的“导入任务链接”，粘贴链接并选择自己的项目。接收者可把共享根任务拖到自己任意任务下，这个本地父级不会影响其他成员的任务结构。
- 新生成的链接会同时记录共享电脑名和可用的 IPv4 地址。如果旧链接中的电脑名在对方电脑上无法解析，可在导入窗口的“共享目录地址”中填写资源管理器能打开的完整地址，例如 `\\10.143.58.8\teamData`；只填写 `\\10.143.58.8` 时程序也会自动尝试其 `teamData` 共享。
- 每个人的 `data` 保存其全部个人任务和团队任务；`teamData` 只保存团队任务交换记录和共享附件。接收方会把附件导入自己的 `data/files`，图片链接不会依赖另一台电脑的本地编号。优先级属于个人配置，不在成员之间同步。只有自己参与的任务不会写入 `teamData`。
- 完整界面和悬浮窗每 15 秒在后台尝试同步。共享路径断开时，本地修改继续保存；重新连接后，评论按添加顺序合并，不同日期进展直接加入，同日各成员的进展增量并列保留。
- 任务名、完成状态、任务状态或遗留事项发生并发冲突时，顶部团队通知入口会一次列出全部冲突，必须逐项选择采用哪一份。评论和进展自动合并，不弹冲突框。
- 每日进展只有当前用户时不显示用户名；同一天出现其他成员记录时会显示所有修改人。评论区可按用户名筛选，导入的其他成员记录保持只读。
- 团队任务默认勾选“更新后通知其他协作成员”。成员更新会出现在顶部团队通知入口，可标为已读；取消勾选后，本机后续修改不再写通知。
- 同一 Windows 用户名在多台电脑上识别为同一个人，各设备的评论和进展会合并。成员用户名用于身份标识，请避免多人共用同一 Windows 登录名。
- 任务链接包含访问团队仓库所需的信息，只应发送给获准访问该任务的成员。删除 Windows 共享权限后，对方即无法继续读取仓库；已同步到对方本地的数据不会自动删除。

## 拖动、序号与优先级
- 悬浮窗任务显示层级序号（如 1、1.1、1.1.1），遗留事项显示清单序号。
- 拖动任务到另一任务行的中央，改为其子任务；拖到行的上、下边缘调整同级顺序；拖到树的空白处或右键“移为顶层任务”可恢复为顶层任务。
- 拖动遗留事项到任务，改为该任务的遗留事项；拖到另一条遗留事项的上、下方调整顺序。
- 拖动仅在当前项目内进行；整个子树随任务移动，不能形成循环或超过 5 级。归属和顺序一起保存，保存失败保留原数据。
- 在完整或简洁悬浮窗中，点击任务或遗留事项名前的优先级文字（如 [P7]），即可修改为 0～9；数字越小越优先。新增任务默认 7，可在“设置”中修改；旧数据未设置优先级时仍按 9 显示。也可通过右键“设置优先级”打开。
- 新事项、新任务和新遗留窗口都可在保存前选择优先级；未手动选择时使用设置中的默认值。
- 在“设置”的“悬浮窗展示哪些优先级”中，可多选需要展示的 0～9 级事项，也可全选或全不选；保存后立即刷新并保留到下次启动。任务右键菜单仍提供同一筛选的快捷入口。子任务或遗留事项符合筛选时，即使父任务不符合，也保留父任务及中间层级；未命中优先级的遗留事项会隐藏。
- 菜单中的“按优先级排序”按同级任务的优先级排列，优先级相同按手动顺序排列；父子结构保持不变。拖动任务后自动切回手动顺序，排序偏好会保留。

## 撤销操作
- 完整界面支持撤销按钮；悬浮窗使用 Ctrl+Z，不占用工具栏位置。
- 支持任务名称、描述、优先级、完成状态，任务新增和删除、当前项目内的归属和排序，以及每日进展和遗留事项的修改；创建子任务及其关联会作为一次操作撤销。
- 两种界面共用当前账户最近 50 组可撤销操作，重启后仍保留。上传的图片文件不会因撤销而删除。
- 在文字输入框内，Ctrl+Z 撤销文字输入。完整界面有未保存内容或正在保存时，请先保存或取消；悬浮窗请先关闭进展或遗留事项编辑窗口，再撤销已保存操作。
- 若另一窗口改动了同一内容，撤销会提示冲突并保留较新的数据；不会强行覆盖。撤销属于逐步恢复，不提供重做。

## 遗留事项图片与查看图片
- 完整悬浮窗先选中任务或子任务，再点击“新遗留”打开管理窗口；简洁模式可双击已有遗留事项管理，需要新增时先回到完整模式。不显示用于添加的“遗留事项”分组或空占位。已有遗留事项直接列在任务下；没有遗留事项和子任务时，不显示展开箭头。有子任务时仍保留层级展开。可选择优先级、输入内容、Ctrl+V 粘贴图片或点击“添加图片”，支持只添加图片。选中已有事项可继续编辑、调整优先级和添加图片；点击缩略图移除待保存图片。
- 完整界面每日进展内的共享遗留事项也支持粘贴或选择多张图片；每条的“添加图片”可继续补图。
- 悬浮窗可通过事项标题前的“图片”或右键“查看图片”打开独立窗口，汇总该任务及下级任务的描述、每日进展和当前遗留事项图片。选中单条遗留事项时只看该条的全部图片。
- 图片随遗留事项保存。跨任务拖动时复制所需附件，删除原任务不会破坏移动后事项的图片；其他事项仍保留原图片。
- 上传或保存失败会保留输入供重试；保存成功再关闭编辑窗口。图片不依赖 Node.js 或外部图片服务。

## 完整界面概览
- 项目按任务分区，子任务和更下级子任务逐级缩进，保留名称、描述、遗留事项和进展四列。
- 点击任务或子任务名称旁的箭头展开、收起；状态保存在当前浏览器，刷新后保留。
- 搜索会临时展开匹配结果的上级关系，清空搜索恢复原收起状态；筛选已完成或未完成时保留匹配子任务的上级。
- 展示模式只用于浏览，修改内容请进入编辑模式。

## 每日进展
- 完整界面：打开任一事项，在“记录每日进展”填写内容。日期默认今天，可改为补记日期；遗留事项改为独立清单，每条单独添加或移除，所有进展日期共享。
- 悬浮窗：选中事项，点击“记录进展”，或双击事项；填写后保存。
- 支持 Ctrl+Enter 快速保存；选择已提交的日期会载入历史内容；同一天的多条旧进展合并编辑，保存后更新当天内容，保留原有图片，不覆盖事项描述。
- 历史进展显示在事项评论记录中，可以继续编辑和添加图片。网页快捷填写区的未提交文字会保留在当前浏览器中；悬浮窗关闭未保存内容时会提示。

## 引用历史进展并更正
- 在新的进展日期中点击“引用历史进展”，表格会列出日期和进展内容；勾选一个或多个日期后点击“确定”。点击“取消”不会改变当前进展，同一天的多条记录会合并为一个引用。
- 在“今日进展”中写更正说明后保存。原记录保持不变，引用保留当时的文字和图片；原记录后来修改或删除，不会改写引用文字。图片沿用原附件，单独删除附件会影响图片查看。
- 保存后可点击“展开/收起引用的历史进展”查看引用快照；被引用的来源记录也会显示“展开/收起引用方的进展”，用于双向核对更正关系。
- 完整界面可通过“查看原记录”在新页面打开来源；历史记录的“编辑当天进展”可继续修改更正说明或移除引用。
- 悬浮窗支持添加、移除引用和“查看快照”，选择表格中还能查看或收起引用方进展；图片可在独立窗口查看。切换日期的草稿、自动保存和撤销均包含引用。
- 展示模式的进展天数范围按新记录的日期计算，即使旧记录已超出范围，新记录内的引用仍会显示。

## Ctrl+V 粘贴图片
- 事项描述：点击描述编辑区，截图或复制图片后按 Ctrl+V，上传完成后保存描述。
- 网页每日进展：点击进展输入区按 Ctrl+V，可连续粘贴多张图片，预览中可移除图片；点击“保存进展”后统一上传并保存。
- 悬浮窗：打开事项的“记录进展”，按 Ctrl+V 粘贴剪贴板图片；窗口会显示已粘贴数量，点击保存后上传。
- 支持只有图片的进展。图片保存为事项附件，历史进展内可查看；普通文字粘贴保持原样。
- 网页尚未保存的图片仅在当前页面内保留，离开或刷新前请先保存。若上传失败，留在页面重试即可；已成功上传的图片会复用。

## 自动保存设置
- 默认开启，每 30 秒检测一次；可设置 5–3600 秒或关闭。
- 网页：用户设置页中的“自动保存设置”，或每日进展内的同名入口。设置保存在当前浏览器，对事项描述和每日进展生效。
- 悬浮窗：顶部“设置”按钮。设置写入 data/autosave.json，对当前进展编辑生效。网页与悬浮窗分别配置。
- 只有文字、日期或图片发生变化才提交，没有变化不重复写入。上传和保存失败保留当前内容，下次检查再尝试。
- 进展自动保存后保留编辑内容，继续修改会更新同一条记录；点击“保存进展”也更新当天内容；切换日期可补记或编辑其他日期。
- 网页自动保存的进展草稿及已上传图片可刷新恢复。未上传图片仍仅保留于当前页面，建议看到保存成功再退出。
- 事项描述在启用自动保存时，关闭事项也会尝试保存当前改动；关闭自动保存后请手动保存。

## 数据保存目录配置
- 双击 Configure-TaskTrace.cmd，或在悬浮窗“设置”中点击“配置数据目录”。
- 选择目录并保存，退出 TaskTrace 后重新启动生效。数据库、图片、会话、悬浮窗设置及自动保存设置统一写入此目录；网页偏好仍保存在浏览器。
- 默认使用程序旁的 data，兼容旧版数据。首次运行生成 tasktrace-settings.json，也可手动修改，例如：

```json
{"dataDirectory":"D:/TaskTraceData"}
```

支持绝对路径、中文、空格、相对程序目录的路径和 %USERPROFILE% 等环境变量。配置文件损坏或目录不可写时会报错，不会自动切换到其他目录。

切换目录不自动搬移数据：如需迁移，请先退出程序，备份并将旧目录全部内容复制到新的空目录，再修改配置并启动。选择已有 TaskTrace 数据目录会直接使用其中的数据。
发布 ZIP 仅含 tasktrace-settings.example.json 示例，不含生效配置，因此覆盖升级不会覆盖原目录选择。升级时保留 tasktrace-settings.json 及其指向的数据目录。
以下说明中的 data 均指配置后实际使用的数据目录。

## 子任务
- 一个项目可以包含多个事项，每个事项还可以继续拆分子任务。
- 网页：打开父事项，在“相关任务”区域输入子任务名称，点击“添加子任务”或按回车。子任务自动归属父事项所在项目；点击名称打开子任务。
- 悬浮窗：选择一个事项，点击底部“子任务”，可查看、新增及勾选完成其子任务。子任务也在项目主列表中显示，选择它即可记录进展。
- 每个子任务都有独立的描述、每日进展、图片和完成状态；子任务完成不会自动完成父事项。
- 若创建成功但关联失败，可点击“重试关联”，不会再次创建相同的子任务。

## 完整模式查看已完成事项
首页“当前任务”标题下增加“任务显示范围”：可选择未完成、全部（含已完成）或已完成。选择会保存在当前浏览器，刷新后仍生效。已完成事项可以点击打开，继续查看进展和图片。
首页原来固定只查询未完成事项，现已改为按选择查询。项目列表仍使用其原有筛选；若项目设置了自定义过滤条件，可在该项目的“筛选”中调整。

## 旧版升级
退出旧版本后，将新版程序文件覆盖到原目录，保留 data。只有一个有效账号时自动沿用原账号及其数据，不修改原密码。若已有多个账号，启动器会提示先在 data/local-user-id.txt 填入要使用的数字用户 ID，避免擅自选择他人的工作区。

## 数据和备份
data/tasktrace.db：本地数据库。
data/files：图片及其他附件。
data/secret.txt：用于保持登录信息有效的本地密钥。
data/local-user-id.txt：固定当前本地工作区所属用户。
data/local-session.json：启动时生成的私有会话，不要分享。
data/browser-session.json：打开完整界面时生成的私有会话，不要分享。
data/team-sync.json：团队任务在本机的任务映射、同步基线和待解决冲突，不要手工修改或分享。
data/floating-window.json：悬浮窗的位置与大小。
data/local-config.yml：每次启动自动生成，不用于手动配置。
data/server.log 和 server-error.log：启动日志。
请先退出服务，再备份或搬移整个 data 目录（包括 SQLite 的辅助文件）。重新解压新版时保留原 data 目录。
需要保留团队协作仓库时，还应同时备份程序旁的 teamData；不要将含真实团队任务的 teamData 放入公开发布包或 Git 仓库。
不要将含个人数据的 data 目录作为公开体验包分发。

## 项目展示模式
- 从侧栏或项目列表进入项目，默认展示紧凑的进展总览。
- 项目是总表，按任务分区，每个子任务占一行，依次显示子任务名、子任务描述、遗留事项和进展。
- 默认包含已完成事项，也可筛选全部、未完成或已完成，按名称查找分区。
- 描述、图片与进展直接显示。进展以“日期：进展”呈现，按每日进展填写的日期倒序排列；遗留事项读取跨日期共享清单，任务自身记录可单独展开。
- 展示模式中不直接编辑内容。点击右上角“进入编辑模式”后，使用原有列表、看板等编辑功能。
- 编辑完成点击“返回展示模式”，重新读取最新进展。再次从项目入口打开时，默认恢复展示模式。

项目列表编辑模式提供“显示已完成任务”开关，选择会自动记住。

## 启动或打开完整界面报错
- 悬浮窗底部显示错误时，点击提示即可查看可选中、复制的完整详情；打开完整界面失败会自动弹出详情。
- 悬浮窗错误保存到配置的数据目录内 TaskTrace-window-error.log；启动脚本失败保存为 TaskTrace-startup-error.log。
- 若数据目录不能写入，启动错误日志会尝试保存到程序目录，再尝试系统临时目录；错误弹窗显示实际路径。
- 提供错误详情或以上错误日志即可排查，不要发送 local-session.json、browser-session.json、local-config.yml 或 secret.txt。
- 打开系统默认浏览器这一步失败时，可先检查 Windows 默认应用中的浏览器设置；具体原因以错误详情内的系统错误码为准。

## 程序图标
TaskTrace.exe、悬浮窗和托盘使用项目自带的 Vikunja 小羊驼图标。可为 TaskTrace.exe 创建桌面快捷方式；请保留同目录的其余程序文件。启动入口仍调用统一的 Launch-TaskTrace.ps1，无需额外安装运行环境。

## 无终端启动
双击 TaskTrace.exe 启动。工作区准备、后台服务和启动脚本均不创建终端窗口；启动失败仍显示错误详情，运行日志继续保存在数据目录。发布包不再包含 Start-TaskTrace.cmd，旧的桌面快捷方式请改为指向 TaskTrace.exe。

## 修改子任务名称
- 完整界面：在任务详情的子任务列表点击“改名”，填写后点击“保存名称”或按回车；“取消”或 Esc 放弃本次修改。
- 悬浮窗：选择父任务并打开“子任务”，选中子任务后在名称栏修改，点击“保存名称”或按回车。
- 名称不能为空；只更新名称，不修改完成状态、进展、描述及父子关系。

## 遗留事项汇总
展示模式展开“任务自身进展”后，遗留事项列保留任务自身内容，并自动汇总所有子任务及下级子任务共享遗留事项清单，标明来源名称。已完成子任务若仍填写遗留事项也会列出；收起和筛选不改变汇总范围。清单中的事项移除后不再汇总；切换进展日期不改变清单。旧版数据首次使用时从最新进展导入遗留事项。点击“刷新进展”读取最新记录；汇总只用于展示，不改写父任务记录。

## 本机账户名称
启动时自动读取当前 Windows 登录账户：界面优先使用系统账户的完整姓名，未设置时使用登录名。登录用户名也使用系统登录名，不支持的字符转为短横线。已有工作区只更新原账户名称，不创建新账户、不改变任务归属；若用户名与库内其他账户冲突，则保留原用户名并更新显示名称。读取不到系统身份时保留已有账户名称。更换电脑或 Windows 账户后，下次启动按当前系统账户更新名称。

## 简洁悬浮窗
- 点击“简洁模式”，隐藏标题栏和完整工具栏。窗口未选中时只保留任务树，底部操作栏及灰色区域一起收起。
- 选中窗口时，底部显示“完整”和右侧的“最小化”；窗口未选中时，按钮和底部区域一起隐藏，任务列表保持原位置。“最小化”隐藏到系统托盘，双击托盘图标可重新显示。
- 任务和遗留事项通过树形箭头直接展开或收起；新增遗留事项需回到完整模式，优先级筛选可从任务右键菜单打开。
- 拖动窗口边缘或四角调整大小；按住事项右侧、层级缩进、列表下方、按钮间隙等空白区域均可移动窗口。任务文字仍用于事项选择和归属拖动，勾选框、展开按钮、优先级和图片链接保持各自操作。
- 展开任务后直接逐条显示遗留事项，没有中间的“遗留事项”分组；没有遗留事项则不显示占位行。有图片的条目在标题前显示可点击的“图片”，点击在新窗口查看该条的全部图片；普通文字仍可拖动调整归属和顺序。
- 没有可见事项时，会提示空项目、搜索、已完成或优先级筛选等原因。点击空白区域或重新选中窗口即可显示操作栏并返回。
- 简洁模式下按 Esc、右键选择“回到完整悬浮窗”，或通过系统托盘同名菜单，也可恢复正常模式；即使没有事项或窗口已隐藏仍可恢复。
- 鼠标停留在任务上，会显示最新日期的进展；双击遗留事项文字可管理清单。
- 进展日期内尚未提交的修改，在同一编辑窗口切换日期时保留为草稿。历史记录合并后，原始评论仍保留用于追溯，展示模式和每日编辑区使用合并内容。
## 概览中的当前任务
- 当前任务按“项目 → 任务 → 子任务”分组和缩进，项目及有子任务的事项均可收起、展开。
- 未完成、全部、已完成筛选继续生效；不符合筛选但有匹配子任务的上级，会标记为“为保留层级显示”，不计入匹配数量。
- 自动读取全部分页；不同项目的事项分别显示，保留名称点击、完成勾选等原有操作。

## 任务层级上限
- 任务最多支持 5 级：项目不计入，项目中的顶层任务为第 1 级，最深可到第 5 级子任务。
- 网页及悬浮窗到第 5 级时禁用新增子任务；已有任务关联也会检查整条上级链和待挂入的完整子树。
- 旧数据不删除、不截断，仍可查看和编辑；新增父子关联不能使层级超过上限。

## 展示模式列宽
- 展示模式支持拖动表头右侧分隔线调整四列宽度，同一项目表格同步对齐；按项目在当前浏览器保存，可点击“恢复默认列宽”重置。
- 聚焦表头分隔线后，左右方向键每次调整 10 像素，Shift 加方向键调整 50 像素。内容过宽时，可在表格内横向滚动。

## 展示模式进展范围
- 在项目展示模式的“进展范围”选择全部、最近 1/7/30 天，或自定义 1～36500 天。设置按项目保存在当前浏览器中，刷新后保留，默认显示全部。
- 每个任务和子任务分别以自身最新进展的记录日期为起点，包含当天，按自然日向前计算。例如最新进展为 9 月 17 日、显示 3 天，则显示 9 月 15～17 日；期间没有填写的日期也计入天数。
- 同一天的多条进展都会显示，日期不明的历史条目保留。被范围隐藏的记录会显示数量提示，可切换“全部”查看。
- 只调整展示范围，完整历史和图片仍保留；任务描述、遗留事项及其汇总不受影响，每日进展编辑继续显示完整历史。
